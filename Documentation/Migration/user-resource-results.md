# User profile and enrollment results

Two shared resource fixes make generated Kotlin calls preserve usable user state. Clearing both profile names now clears `fullName` on the existing resource. Removing a profile image now accepts the backend's image deletion receipt without projecting undefined image fields: the returned `ImageResource` has the receipt ID and null name/public URL, and the returned client clears the user's image state. Complete image responses and rejected deletions remain covered. These changes live in TypeScript `User` and `Image`, with no Kotlin domain service or relaxed projection type.

`NativeCoreTests/Android/UserResourceTest.kt` exercises five scenarios on packaged QuickJS: null names, empty names, image receipt, profile-plus-metadata replacement, and TOTP enrollment/failed verification/successful verification/backup/removal. The first three failed on the preceding bundle; all five now pass. The full deterministic instrumentation run passes 89 tests, excluding only the separately opt-in benchmark and live-startup classes. Apple's equivalent suites pass 86 macOS and 83 iOS Simulator tests; Swift counts the parameterized declaration once.

The shared additions contain 27 generated user-resource cases and one explicit Apple-token linking case. All 428 embedded tests pass, along with 33 relevant source tests, TypeScript compilation, generated-contract checks and bundle/Expo attached-transport reproducibility. Coverage includes profile clearing, image receipts and upload payloads, five metadata replacement paths, direct deep-merge metadata, password options, invitation/suggestion/membership pagination, leaving an organization, user deletion, and TOTP/backup results. Existing contact and session-revocation suites cover those user entry points. External-account checks complete the browser callback and client reconciliation, or use Apple identity; an explicitly supplied Apple token is preserved without another host identity request and excluded from observed state.

Migration details:

- `User.update` with deprecated unsafe metadata replaces the document using a patch computed from a fresh reload or profile response. `updateMetadata` applies an explicit merge patch. Kotlin does not duplicate this algorithm.
- User invitations accept one generated status, not the old array input. Omit status for the old empty-array behavior. Suggestions support multiple statuses through their generated union's `Case3`; empty arrays are omitted. Pagination uses `initialPage` and `pageSize`.
- The configured native callback owns external-account browser return routing. Per-call redirect overrides do not replace it. OIDC prompts use a space-separated string, while scopes remain a list.
- TOTP and recovery-code objects are explicit result values, excluded from general observation. Read enrollment flags from the generated user after completion.
- Profile image deletion uses `setProfileImage` with null file. Binary upload values contain filename, MIME type and bytes. Shared tests validate host payloads; they do not establish a live Android multipart upload.
- Effective PATCH/DELETE uses POST plus `_method`; canonical Boolean form values are `true`/`false`. User session collections are shared-resource state rather than the removed native global cache. User deletion and organization departure reconcile the server's returned client; receipt-only responses are not evidence of an independent native sign-out policy.
