# Shared client credential deletion

Core `acb9a3e1a18bbc22e1294f6716e77ffb3f0b731c` fixes native client deletion credential handling. The backend sends `Authorization: Bearer ` as an explicit clear marker; the shared transport previously stored it as a credential. It now removes the credential within its acceptance queue and advances the revision so older replies cannot restore it. Storage failures propagate, and request preparation waits for queued removal. Non-native transport behavior is unchanged.

The supported deletion path uses the existing Expo JavaScript owner with `experimental.persistClient: false`. Canonical `Clerk.signOut()` calls `Client.destroy()`, which resets client resources, while the attached projection publishes empty session and user roots. Standalone sign-out retains the canonical default that persists the client and removes its sessions. This change does not introduce a native state reducer, arbitrary response-to-client-nil behavior or a new native load option.

Expo also supports custom caches that implement only `getToken` and `saveToken`. Both server clearing and configuration changes now save an empty client credential when `clearToken` is unavailable, preserving unrelated entries. A provided `clearToken` failure is reported normally.

Both generated attached-core deletion cases failed against the previous bundle and now pass. They use the real JavaScript owner, verify credential and resource clearing, and then create a new client without the old credential. Type checking, the Expo build including declarations and bundle reproducibility pass. The complete packaged-core contract suites pass 104 tests on macOS, 101 on iOS Simulator and 112 on Android. Android excludes the separately opt-in benchmark and live-startup classes. The server behavior is pinned to [the client deletion handler](https://github.com/clerk/clerk_go/blob/33e0f8279c9b4e3d90d6e4788c67237bc6378a56/api/fapi/v1/clients/http.go#L306) and its [native credential clear helper](https://github.com/clerk/clerk_go/blob/33e0f8279c9b4e3d90d6e4788c67237bc6378a56/api/fapi/v1/cookies/helpers.go#L192). These deterministic checks do not claim a live Expo application journey or an assertion-level retirement of Android legacy networking tests.
