# Browser manager assertion audit

All thirteen declarations and complete assertion bodies in `source/api/src/test/java/com/clerk/api/sso/SSOManagerActivityTest.kt` were reviewed against baseline `1ea9f97250e9e3b266b7fbcfe37d9373e4fc393f`. The file is retired. [The proof](evidence/browser-manager/proof.json) retains its original hash, declaration names, current source hashes and named replacement reports.

The current activity owns presentation only. It returns a matched callback through the pending native continuation, then finishes. Generated TypeScript resource operations own callback interpretation and server reconciliation. There is no activity-owned coroutine that selects between hosted authentication, sign-in, external accounts and email-link services, and no public activity-result protocol for consumers to preserve.

| Legacy declaration | Current disposition |
| --- | --- |
| `authorizationComplete_setsResultOk_whenDataPresent` | `actualReceiverDeliversCallbackToTheRunningManager` returns the exact callback URI through the suspended native host operation and verifies cleanup. Android `RESULT_OK` is replaced by the callback result; success does not independently activate a session. |
| `callbackIntent_completesWithoutAuthorizationStarted` | The old construction helper and authorization-started extra are removed. Completion now requires a currently owned pending browser operation. The normal receiver and rotation cases verify completion through that owner. The old behavior of calling a native service from a standalone response intent is not retained as an unsolicited completion API. |
| `errorCodeOnlyCallback_completesWithoutAuthorizationStarted` | The host delivers matching callback query data unchanged; `BrowserHostTest.mismatchedAndDuplicateCallbacksCannotCompleteAnotherRequest` checks an error-only query. `BrowserCallbackContractTest` checks generic provider error reconciliation and a recognized native failure through the actual core. The old activity result code and special native query interpretation are removed. |
| `newAuthorizationIntent_restartsManagerWithNewUrl` | Direct activity replacement is removed. Concurrent host calls are rejected without replacing the first request, as checked by `concurrentPresentationDoesNotReplaceTheFirstRequest`. Sequential authorization remains supported: `immediateSecondAuthorizationIsPresentedAfterFirstCallback` verifies both actual manager launches and exact distinct URLs. |
| `authorizationCanceled_setsResultCanceled_whenNoData` | `resumedManagerTreatsBrowserDismissalAsCancellation` performs Back from the foreground stand-in and requires `user_cancelled` and cleanup. The two old native service-cancellation calls and `RESULT_CANCELED` are removed. Generated sign-in/sign-up cancellation cases separately require no reconciliation or activation. |
| `authorizationUrl_isNotTreatedAsCallback_whenBrowserIsDismissed` | Browser authorization data lives in the manager's URL extra, and actual dismissal produces typed cancellation rather than callback success. `launchesExplicitNonExportedManagerWithOpaqueRequestId` verifies the exact authorization URL and absence of intent data. The native callback matcher rejects another route. |
| `hostedAuthCallback_callsOnlyHostedAuthService` | Hosted-portal authentication and the old native service dispatcher are unavailable in the selected profile. This service-call assertion is intentionally removed; browser OAuth/enterprise SSO is not claimed to replace that protocol. |
| `hostedAuthCallback_reattachesAfterConfigurationChange` | The old hosted-service reattachment contract is removed with that protocol. `browserCallbackSurvivesDeviceRotation` proves current browser callback delivery through a recreated manager, but is not presented as hosted-portal coverage. |
| `authorizationComplete_isCalledOnlyOnce_whenResumedTwice` | Pending host completion clears ownership before resuming the caller; the host duplicate/late-completion test verifies a resolved request cannot complete again. The actual receiver test verifies callback delivery and manager cleanup. The old mocked service call count is removed. |
| `authorizationComplete_setsResultOk_evenWhenServiceThrows` | Despite its name, the old assertion requires `RESULT_CANCELED` after swallowing a coroutine exception. The current manager does not await a domain service. Generated browser transport and native-callback failure checks require structured failure rather than success; the host failure checks require typed presentation errors and cleanup. |
| `externalConnectionFlow_callsOnlyCompleteExternalConnection` | Native service selection is removed. `OAuthProviderRequestTest` executes generated `User.createExternalAccount` through the packaged core, checks browser presentation and canonical external-account reload/result, and does not invoke the sign-in service. The activity receives no separate account-connection state machine. |
| `completionStarted_persistsAcrossConfigurationChange` | The activity no longer stores domain completion state or owns its coroutine. The real rotation test preserves browser delivery without another launch; `foregroundDuringOAuthRedemptionWaitsForAuthentication` separately suspends actual core redemption, sends lifecycle events, and requires complete sign-in with one deferred client refresh and no stale-credential error. That core test simulates native lifecycle events and does not itself rotate an activity during HTTP. |
| `nativeMagicLinkFailure_setsResultCanceled` | The old native service result wrapper and activity result code are removed. Email-link handling is an explicit generated `Clerk.handleAuthCallback` operation. `signUpCannotConsumeSignInTicket` exercises a completion failure through QuickJS, requires `invalid_email_link_response`, no observable callback result and no session activation. This proves the current error contract, not the old activity-result protocol. |

The [callback receiver audit](callback-receiver-test-audit.md), [browser lifecycle proof](browser-activity-lifecycle.md), [browser host audit](browser-host-test-audit.md), [generated SSO audit](browser-sso-test-audit.md) and [provider request audit](oauth-provider-test-audit.md) retain the related sources and reports. Current API 36 emulator checks of foreground/redemption ownership and email-link completion failure are also preserved in this proof. No TypeScript or runtime source change was required for this manager assertion retirement.

Real Chrome/custom-tab integration, live hosted-provider authentication, process-death recovery and released-app upgrades remain separate product/release work. A removed old service assertion is not counted as a newly passing test or as support for an unavailable feature.

The related host, browser callback, provider and activity scenarios passed [CI at the unchanged runtime revision](https://github.com/clerk/clerk-android/actions/runs/34532588337), `c5a8631bc8123d7fc588f8ffb5f7dca0f6192301`. The two additional core scenarios were run separately on the local API 36 arm64 emulator and verified against their exact method names. The manager retirement changes documentation and an excluded legacy test file; it does not change the compiled SDK or current test sources.
