# Email-link flow import and completion

The shared `NativeMagicLink` importer now rejects unknown or null legacy Android flow states before redeeming a verifier. Android's previous `PendingNativeMagicLinkState` decoder rejected invalid values; interpreting them as sign-in was a regression. Recognized `SIGN_IN` and `SIGN_UP` states continue to work. Older iOS records with no `kind`, or a null `kind`, intentionally default to sign-in, matching their previous decoder.

`NativeCoreTests/Android/EmailLinkCompletionTest.kt` adds eight generated QuickJS checks: unknown/null Android states, absent/null iOS kinds, valid Android sign-in, incomplete sign-in/sign-up continuation and rejecting a sign-in ticket for a sign-up flow. They verify canonical result identity and remaining requirements, observer callback state, verifier consumption, no unintended HTTP and explicit finalization. The equivalent Swift suite exercises JavaScriptCore. Fixtures exercise cross-platform migration parsing without claiming a live released-app upgrade.

The expanded shared callback suite also tests wrong sign-up IDs/null results, preservation of a newly prepared verifier while an old completion is suspended, all terminal cleanup codes and retryable HTTP failure. Starting a new flow invalidates the older callback before its ticket can be used. Direct authentication parameter tests preserve provided Apple tokens, ticket strategies, names, metadata and consent; generated calls expose explicit transfer/finalize decisions in place of old native convenience methods.

The iOS `auth-flow-test-audit.md` accounts for all 40 old native Auth declarations and identifies intentional new-major API differences. No Android legacy files are retired by this change. The SwiftUI presentation test separately verifies a retained session remains behind the completion gate after a finalization error; that is not visual UI or OS-authentication evidence.

Before the importer correction, all four invalid-state shared fixtures redeemed their verifier. Both native engines reproduced the two selected invalid-state cases; the other six new native scenarios passed. With the corrected core, all 521 shared embedded tests pass (40 email-link cases, including terminal/nonterminal cleanup). Full packaged suites pass: 103 tests on macOS, 100 on iOS Simulator and 111 on Android. The 11 `AuthFlowCoreTests` pass on both macOS and iOS Simulator, including the recovered-session finalization-error gate. TypeScript checking, generation (342 types, 1,551 members, zero unsupported shapes), and reproducibility checks pass, including the Expo attached transport. The macOS runs retained existing CoreData/NSXPCConnection and linkd registry warnings without test failures.
