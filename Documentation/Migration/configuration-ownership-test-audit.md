# Configuration ownership and device-token assertion audit

This audit covers every assertion in `ClerkConfigurationSwitchTest.kt` (three declarations) and `ClerkDeviceTokenUpdateTest.kt` (six declarations) at baseline `1ea9f97250e9e3b266b7fbcfe37d9373e4fc393f`. The setup helpers mutate the removed `ConfigurationManager` through reflection or mock its old native domain services. Those helpers are not part of the generated major's architecture.

## Current owner proof

`NativeCoreTests/Android/ConfigurationOwnershipTest.kt` connects two instances through their own packaged QuickJS runtimes and real Android Keystore-backed credential stores. Each uses a different publishable key, credential, and frontend API host. It checks the scope in each storage request and the host/authorization of HTTP requests. The second owner starts with a signed-in fixture session.

While the first owner's generated SSO call is suspended in HTTP, the test closes that owner and observes host cancellation, `runtime_disposed` on the pending caller, and invalidation of its retained sign-in handle. The second owner's session/user remain visible and a generated reset still works. Reopening each secure store preserves its own credential: closing a runtime does not sign out or erase credentials. An explicit removal of the first store then survives reconstruction without modifying the second store.

The test passes on the Android 16 emulator with one discovered test and no failures, errors, or skips. This is evidence of independent owner/tenant isolation, cooperative host cancellation, and durable scoped storage. It is not a live-account test, an old-major app upgrade, or a guarantee about arbitrary custom capabilities that ignore cancellation. The existing credential-upgrade audit covers import and durable suppression of old records.

## Complete legacy mapping

| Old declaration | Assertion disposition |
| --- | --- |
| `reset clears local configuration and runtime auth state while preserving device id` | Old `reset` deleted credentials and caches, cleared singleton client/session/user/environment/key/proxy/URL/debug/initialized fields, and preserved the installation device ID. The singleton and its fields no longer exist. `close()` cancels the owner and invalidates handles but deliberately preserves its credential; the packaged test verifies both. There is no reset-compatible cache/device-ID manager. Server sign-out remains an explicit generated operation. Closing must not be documented as local sign-out. |
| `switchConfiguration resets and configures the new tenant synchronously` | Mutable key/proxy/base-URL/versioned-URL/debug assignment is removed. Applications connect and retain a new owner, then close the old one. Connect suspends until initialization succeeds. The packaged test verifies distinct request origins, credentials, storage scopes, and owner lifetimes. Proxy and mutable debug options are not retained. |
| `initialize after configuration is a no-op and does not partially mutate options` | There is no repeated global initialization or silently ignored configuration. Each `connect` creates an owner; the isolation test verifies a second connection leaves the first owner's origin and credential intact. Old proxy/debug singleton assertions are retired. |
| `updateDeviceToken fails when Clerk has not been initialized` | Public live device-token replacement is excluded from this prerelease profile. Its pre-initialization failure and exact old error message are removed with the method, not mapped to an unrelated generated operation. |
| `updateDeviceToken rejects blank tokens` | The removed public method's blank-value validator is not retained. Publishable-key validation and credential migration validation are separate contracts; they are not claimed as equivalent tests. |
| `clearDeviceToken fails when Clerk has not been initialized` | The old public runtime clear method and its initialization error are removed. Explicit credential-store removal is a storage operation; it must not be used as a live owner/session transition. |
| `updateDeviceToken persists token and refreshes client state without default client lookup` | Live token injection, mocked `Client.getSkippingClientId`, `Client.get` call counts, and the private environment refresh path are removed. The old test implicitly selected its returned pending session/user. Current HTTP/persistence and session adoption belong to TypeScript; custom tokens must not be injected into an active owner to recreate the old native state machine. The new owner test establishes scoped startup credentials and canonical startup session projection, not compatibility with this removed API. |
| `clearDeviceToken removes token and refreshes client state without default client lookup` | The old native clear-then-refresh-then-clear sequence, token-cache size introspection, replacement client/environment, and mocked service call counts are retired. Generated sign-out and explicit owner disposal are distinct operations. Durable storage removal is independently checked through actual Keystore and reconstruction; it does not assert a live session transition. |
| `reinitialize remains a no-op when Clerk is already initialized` | Global reinitialization and its Boolean no-op result are absent. New owner connection is explicit and suspending; failure does not partially replace a previously retained owner. |

Both old files are retired after this review. Their baseline hashes and declarations remain in `legacy-tests.json`. Other retained SDK and request-race suites still require their own assertion review; these nine declarations are not a substitute for that work.
