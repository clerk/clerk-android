# Browser service assertion audit

All seventeen declarations and complete bodies in `ExternalAccountServiceTest.kt`, `SSOServiceTest.kt` and `SSOServiceCancellationTest.kt` have been reviewed against baseline `1ea9f97250e9e3b266b7fbcfe37d9373e4fc393f`. Their original hashes and names are retained in [the inventory](legacy-tests.json) and [this proof](evidence/browser-host/proof.json). The three old files are retired. The seven declarations in `SSOServiceTest` were already disabled by its class-level `@Ignore`; they are not counted as previously passing coverage.

Android owns a single pending browser presentation and its cancellable continuation. It does not own a second sign-in or account-connection state machine. The generated `Clerk.authenticateWithSSO` and `User.createExternalAccount` methods execute TypeScript orchestration. Native callbacks are delivered unchanged for that orchestration to interpret. No production code changes were needed for this audit.

## Additional native host checks

Concurrent presentation is rejected without replacing the first pending request. Wrong request IDs and callbacks with another scheme, host, port, path or user info cannot complete it; duplicate callbacks are harmless. A valid callback containing provider query data is delivered unchanged. Missing presentation, invalid URLs, an unregistered callback and a failed manager launch fail with explicit errors, without leaving pending work.

`BrowserHostTest` runs on Android with real framework Intent and PackageManager behavior, including the merged manifest. A test Activity intercepts `startActivity`; these checks do not launch a real browser or establish its lifecycle, process restoration or live authorization. `BrowserCallbackContractTest` executes the packaged QuickJS core with deterministic HTTP/browser capabilities. Actual browser/device integration remains a release gate.

The current authentication gate requires 78 named cases across eleven suites, including eight host cases and five callback/preparation cases. The proof retains canonical XML and source hashes; no overlapping targeted and gate executions are added together as distinct coverage.
