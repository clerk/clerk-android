# Biometric persistence and enrollment recovery

The shared TypeScript biometric owner now preserves the raw metadata list during mutations. Enrollment, revocation, validation and cleanup no longer discard another app's incomplete or future-format records. Selection decodes only usable records; old Android snake-case entries remain readable without rewriting unrelated entries. Invalid JSON and non-array documents fail before enrollment creates a key or prompts the user. Incomplete individual entries remain preserved but cannot be selected.

When enrollment returns an existing credential ID with a new key, the old key is deleted only after the replacement metadata is saved. Failed optional cleanup preserves a successful enrollment or server revocation. In particular, a read failure after saving enrollment no longer deletes its new key, and a local read failure after revocation no longer hides the returned server result.

Enrollment is bound to its initiating session. Loss of that session rejects adoption; a selection change during persistence rolls back newly saved metadata where cleanup succeeds. After successful server enrollment, failed local adoption attempts server rollback using the initiating session. Shared `FapiClient.request` now honors an explicitly supplied session ID instead of overwriting it with the current selection. Omitted session IDs retain the existing selected-session behavior.

Rollback and key cleanup are best-effort after remote effects. The tests verify accepted rollback and failure paths, not guaranteed live rollback after server-side revocation or device lock. Failed user cleanup retains a pending journal for retry. Kotlin still executes platform storage/key/prompt operations; it does not calculate a second selection, metadata or enrollment state machine.

`NativeCoreTests/Android/BiometricMetadataTest.kt` runs eight generated QuickJS scenarios: enrollment preserves raw entries, user cleanup preserves unrelated entries, corrupt storage fails safely, same-ID replacement deletes the old key, revocation survives a local read failure, saved enrollment survives a cleanup read failure, list values retain dates and typed fields, and loss of the initiating session triggers rollback. Seven failed against the preceding bundle; list projection already passed. The equivalent JavaScriptCore cases and fourteen retained Apple key/encoding tests are also exercised.

The shared biometric suite now has 80 cases, including exact HTTP fields, active/pending/signed-out eligibility, Apple and Android default policies, multiple users/apps, newest/ID/hint selection, server missing/revoked/error outcomes, hidden challenge/signature values, cancellation and cleanup retry. Its returned credential fields use the generated open unions and date types. It remains an explicit-finalization sign-in path.

All 483 embedded tests pass, including the 80-case biometric suite. Runtime TypeScript compilation, generation (342 types, 1,551 members, zero unsupported shapes) and bundle/Expo attached-transport reproducibility pass. The FAPI source suite passes 48 tests, with one pre-existing skip and four TODOs. The complete native suites pass 101 macOS tests in 15 suites, 98 iOS Simulator tests in 15 suites and 97 Android instrumentation tests. Swift counts the parameterized metadata declaration once. Android invokes the runner directly, excluding only the separately opt-in live-startup and benchmark classes.

The iOS assertion audit maps all 96 declarations in its five old biometric files to current owners or explicit removed APIs. This document does not retire Android legacy tests. The removed native local-store/global-clear APIs are not replaced by an all-app cleanup operation; generated user cleanup is scoped to the current app. These fixtures do not establish a real old-major app upgrade, physical credential presentation, actual uninstall/restore, multi-owner synchronization or live service cleanup. Those remain release gates.
